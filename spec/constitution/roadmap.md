# Roadmap

_Orden y estado de las features. Cada entrada apunta a su carpeta en `features/`._

## Hecho ✅

1. **001 · Fundación del proyecto** — Ionic React 8 + TypeScript estricto + Capacitor 8 (Vite), estructura de carpetas de `tech-stack.md` §3, ESLint + Prettier, cliente Axios único (`services/api/apiClient.ts`, `withCredentials: true`), taxonomía de errores tipada (`services/api/errorMapper.ts`), logger propio con redacción (`services/telemetry/logger.ts`), storage no sensible sobre `@capacitor/preferences`, `QueryClientProvider` + `IonReactRouter` + tema claro/oscuro, componentes base `AppButton`/`AppPage`, Vitest con pruebas de humo (9 tests). Migrado a Yarn (unifica con el backend). Plataformas nativas Android e iOS agregadas y validadas con builds headless reales (`gradlew assembleDebug` → `BUILD SUCCESSFUL`; `xcodebuild` para simulador → `BUILD SUCCEEDED`). App exclusivamente nativa — nunca web/PWA; `yarn dev` es solo atajo de desarrollo. Sin pantallas de negocio ni login real — eso empieza en `002`. Ver `spec/features/001-fundacion-proyecto/`.
2. **002 · Autenticación** (alcance navegador/dev) — Login/logout/sesión real contra Keycloak vía proxy de Vite (mismo origen en dev, sin tocar el backend). `ProtectedRoute`/`PublicRoute`/`RoleGuard`/`PermissionGuard` implementados y probados. **Validado con Chrome headless real contra el backend corriendo local** (Postgres + Keycloak + Next.js): login, identidad real en pantalla, persistencia tras recarga, logout, deep-link protegido, guards de rol/permiso con un usuario real sin permisos. Se encontró y corrigió un bug real de TanStack Query en el logout (`clear()` → `resetQueries`). Ver `spec/features/002-autenticacion/`.
3. **003 · Autenticación nativa (Android/iOS empaquetados)** — Formulario nativo de usuario/contraseña (`AppInput` + React Hook Form + Zod) que llama a `POST /api/auth/mobile/login` y recibe `Authorization: Bearer`. **Revisado el mismo día**: se implementó primero con Authorization Code + PKCE + navegador in-app (validada parcialmente), pero el usuario pidió reemplazarla por un formulario nativo (estilo Facebook) — decisión de producto que implicó Resource Owner Password Credentials del lado del backend, confirmada explícitamente por el usuario tras explicarle el riesgo. Token guardado en `@aparajita/capacitor-secure-storage`. **Validado de punta a punta en un emulador Android real** (no un mock): login real, identidad real en `/home`, logout real, sesión persistente tras matar y reabrir la app. En el camino se encontraron y corrigieron 6 gaps de infraestructura reales (Mixed Content, App Transport Security, `usesCleartextTraffic`, CORS ausente en el backend, `withCredentials` incompatible con CORS abierto, header `X-Correlation-ID` fuera de la lista de CORS) — ninguno evidente por adelantado, todos aparecieron probando contra el sistema real. Ver `spec/features/003-autenticacion-nativa/spec.md` para el detalle completo.
4. **004 · Rediseño visual de login y home** — Login web/dev y nativo modernizados con `AuthShell`, tokens semánticos claro/oscuro, formularios accesibles y layout adaptable inspirado en una jerarquía visual familiar sin copiar marcas externas. `Home` convertido en panel de cuenta con iniciales, identidad, roles, estado vacío y resúmenes condicionados por `RoleGuard`/`PermissionGuard`, sin datos ni accesos ficticios. Sin cambios de API, autenticación o dependencias. Validado con lint, TypeScript, 27 pruebas, build web, Capacitor sync y builds headless Android/iOS. Ver `spec/features/004-rediseño-login-home/`.
5. **005 · Rutinas gamificadas** — Identidad Pasitos Mágicos aplicada a metadatos web, Android e iOS; home con tareas y hábitos diarios, progreso, estrellas, racha y recompensas visuales/auditivas. Incluye un reporte local para padres y docentes con avance, siguiente actividad pendiente y refuerzo positivo, sin inventar endpoints. Ver `spec/features/005-rutinas-gamificadas/`.

## Siguiente 🔜

6. **006 · Entrada nativa y registro de usuarios** — Registro e inicio de sesión validados en el emulador. Las cuentas se almacenan en PostgreSQL mediante Prisma, las contraseñas usan hashes `scrypt` con sal aleatoria y los usuarios existentes migran su contraseña al iniciar sesión. La persistencia fue comprobada creando una cuenta, reiniciando el backend y autenticándola nuevamente. Ver `spec/features/006-entrada-y-registro-usuarios/`.
7. **007 · Cumplimiento del entorno móvil** — En curso. PATH de Android, política de red acotada, README y carpeta de evidencias configurados; quedan las capturas y la validación manual desde una nueva terminal. Ver `spec/features/007-cumplimiento-entorno-movil/`.
8. **008 · Sistema de diseño accesible y catálogo** — Implementación terminada y validada automáticamente: inventario derivado de API, tokens, contraste AA, catálogo, estados y pantalla real. Pendiente únicamente del recorrido auditivo manual con TalkBack antes de moverla a “Hecho”. Ver `spec/features/008-sistema-diseno-accesible/`.
